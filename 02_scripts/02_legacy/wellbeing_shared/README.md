# Wellbeing papers — shared preparation and helpers (frozen legacy layer)

Used by `05_papers/03_resilience_cost` and `05_papers/04_price_of_progress`. The two papers were one project (`resilwb`) until
14 November 2026. Everything both of them need, and nothing else, lives here so that neither paper duplicates processing.

| File | Role |
|---|---|
| `01_build.py` | Legacy provider read (student file and questionnaire-timing file) → `01_data/derived/resilwb_students.csv.gz` |
| `02_prepare.R` | Sample, within-system standardisation, skill index, ESCS quartiles, response-style indices → `resilwb_analytic.rds`, `resilwb_coverage.csv` |
| `00_survey_helpers.R` | Fay BRR + Rubin estimator, weighted moments and quantiles, school fixed effects by demeaning, random-effects pooling, per-system runner |
| `compare_outputs.R` | Compares a fresh estimation directory with a reference, file by file |
| `HISTORY_resilwb_2026-11-14.md` | Unedited analysis notebook of the combined project before the split |

## Status and rules

- **Legacy, not migrated.** `01_build.py` reads the provider file and `02_prepare.R` constructs variables, which the repository
  reserves for `02_scripts/01_harmonization`. This layer must be migrated there before fresh processing counts as maintained.
  Until then it is preserved as it ran on 14 November 2026.
- **Frozen.** The paper sessions do not edit this folder. A change here alters both papers: make it deliberately, re-estimate both
  papers into new directories (`run_all.sh estimate <new_dir>`), compare (`run_all.sh compare <new_dir>`) and record the outcome
  in both papers' `01_code/README.md` before promoting anything to a snapshot.
- `WELLBEING_DERIVED=<dir>` redirects the prepared inputs, so the preparation can be re-run without touching `01_data/derived`.

## Validation of the split — 14 November 2026

No file in `01_data/derived` or in either paper's `04_output` was regenerated by the split; the saved estimates were moved.
To check the relocated code, every step was then re-run into a scratch directory and compared with the saved files:

- `01_build.py`: decompressed extract identical (SHA-256). `02_prepare.R`: analytic file (510,699 × 155) and coverage table equal.
- Paper 03, steps 03–07: 13 result files, maximum absolute difference 0.
- Paper 04, steps 08–09: 6 result files, maximum absolute difference 0 (run twice, the second time through `run_all.sh estimate`
  after the 20-system table became `01_code/systems.R`).
- Both reports re-rendered from their snapshots; extracted PDF text identical to the pre-split PDFs except the reproduction footer.

This establishes that the relocated code reproduces the 14 November estimates on this machine. It does not certify the legacy
preparation against the central harmonizer, and it does not establish that the estimates are correct.
